# Codex design system

Palette **Nord Frost (deepened)**, Inter for all text, **compact** density, light and dark themes. Used for every screen. The app shows a lot of information at once, so it stays **professional and compact**: small type, tight spacing, quiet surfaces, and colour only where it carries meaning.

| File | What it is |
|---|---|
| `tokens.css` | Source of truth: CSS custom properties for colour, type, space and density, plus light/dark theming. |
| `tokens.json` | The same values in machine-readable form, for non-CSS consumers. |
| `brand/` | The logo: `codex-mark-{light,dark}.svg` (the square mark on its own), `codex-logo-on-{light,dark}.svg` (mark plus the **Codex** wordmark, Inter 700 converted to outlines so it renders where Inter is not installed, as in the README), and `favicon.svg`, which switches between the two marks with the visitor's theme. Leave clear space of at least half its width around the mark; don't recolour, stretch or rotate it. |
| `screens/library.html` | Reference Library + Series screen, with the New book, Import and Series settings dialogs, the ⌘K palette, and books shared with you. Open it directly in a browser; there is no build step. |
| `screens/plan.html` | Reference Plan screen inside the book workspace chrome. |
| `screens/write.html` | Reference Write screen: the manuscript editor, Scene Beats and AI drafts, and read-only Write for the view and comment roles (#80). |
| `screens/references.html` | Reference References screen: sources, copyright clearance, permission requests and the bibliography. |

| `screens/print.html` | Reference Layout view: print preview, layout templates, preflight and Export for printer. |

## Rules

- **Tokens only.** Every colour, font size, radius, gap and control height comes from a `var(--…)` in `tokens.css`. Book covers and printed pages are the exceptions: they are the book's artwork, render the same in both themes, and pages use the template's own fonts.
- **Both themes, every time.** Build against the semantic tokens and check the screen in light and dark (the Preview panel in `screens/library.html` switches them). Theme resolution: OS preference by default, forced by `<html data-theme="light|dark">`.
- **Compact by default.** Use `--control-height`, `--row-height`, `--bar-height` and `--cover-width` for sizing so `<html data-density="comfortable">` loosens the whole screen in one switch. The mobile app uses `data-density="touch"`, which also raises the type scale (body 15px) and makes rows 44px.
- **Accent is for action and state:** primary buttons, focus rings, selection, progress, the *Writing* status. Use `--color-accent-soft` for selected and hover backgrounds. Surfaces stay neutral.
- **Book status colours** come from `--status-*` (planning → info, draft → muted, writing → accent, revising → warn, published → ok), shown as a 6px dot plus a label.
- **Type scale:** `--text-lg` for screen titles, `--text-md` for section headings, `--text-base` for body, `--text-sm` for controls and table cells, `--text-xs`/`--text-2xs` for meta and overlines. Weights 400/500/600 only.
- **Codex category colours** (#3) are a separate palette from these UI tokens: `--category-blog|law|story|research|person`. Use them only to mark Codex entries (a 7px square, or a chip tinted with `color-mix(in srgb, var(--category-x) 14%, transparent)`), never for UI state.

## Library screen patterns

The reference in `screens/library.html` defines these patterns; reuse them on other screens.

- **Shelf tile:** a 2:3 cover at `--cover-width`, then an overline (`Book 003`, in a series only), a two-line-clamped title, a 3px progress bar (words ÷ target), a meta line (`72.3k words · 2h ago`) and the status.
- **Series stack (#7):** up to three covers, each offset 7px right and 5px down and progressively darker, with a book-count badge. Clicking it opens the Series screen.
- **Toolbar:** primary action first (`Create Novel`), then secondary (`Import`), a spacer, then search, Sort, Group, and a Grid/List segmented control.
- **List view:** a dense table with group rows per series, tabular numbers right-aligned, and accent-soft row hover.
- **Opening a book:** a tile or list row opens on click or Enter, on the screen last used in that book (`codex.last.<id>`), else Plan.
- **Series in the URL:** `library.html#series=<id>` opens the Series screen. Opening and leaving a series updates the hash, so the browser Back button and a book's Back link return to it.
- **Dialog:** a modal over a dimmed screen, `--radius-lg`, at most 440–500px wide (full width on a phone). A header with the title and ×, label/field rows, then a footer on `--color-bg` with a hint, Cancel and the primary action. Enter submits, Esc or a click on the backdrop closes, Tab stays inside, and focus goes back to whatever opened it.
- **New book:** Title, Author (defaults to you), Series, Number (only in a series, pre-filled with the next number) and Target words. Opened from a Series screen it pre-fills that series. Create opens Plan.
- **Import:** step 1 picks a source (Markdown folder, Novelcrafter export, .docx) and takes a file in a drop zone. Step 2 lists what will be created, count → destination, skipped items in warn, and links to the import mapping (#10). Import opens the new book's Plan.
- **Series settings:** name, description and book order (drag the ⠿ grip, Alt+↑/↓ on it, or the arrows; numbers follow the order), with a note that series Knowledge base categories are shared by every book in it.
- **Shared with you (#80):** the Library lists your books and the books shared with you, directly or through a series. A shared tile adds a *Shared by Mara Lind* line (person icon, two lines at most) and a role chip: **View only**, **Comment** or **Edit**, in the quiet chip style of #26 F-06 (`--color-surface-2`, muted text, an icon). List view adds an **Owner** column (*You* or the owner's name), the chip after the title, and the owner on a shared series' group row. A shared series opens with all its books, *Shared by* and the chip under its stats, and no Series settings or Add book. When only some books in someone else's series are shared with you, those books show under the series heading with a note (*Kofi Mensah shared one book in this series with you. Only that book appears here.*); the other books and their count never appear. A shared book opens in Write. New book only offers your own series.
- **All / Mine / Shared with me:** a segmented control before Sort, kept in the hash (`library.html#filter=mine|shared`). Shared with me with nothing shared says *Nothing is shared with you yet. When someone shares a book or a series with you, it shows up here.*
- **Command palette (⌘K / Ctrl+K, or click the `⌘K` key):** a search field over results grouped as Books (with series and number), Series and Actions (Create novel, Import, Switch view, Toggle theme). ↑↓ moves, Enter opens, Esc closes. A book opens as from its tile.

## Plan screen patterns

`screens/plan.html` defines these patterns.

- **Book workspace chrome (#6):** a header bar with back, settings, cover, title and author, and a sidebar toggle; then the **Plan · Write · Chat · Review** tabs, the scope selector with word, page and read-time counts, a save-status dot, and Format and Focus. The left sidebar is the **Knowledge base**: search with a filter (funnel) that hides categories from the list, `New Entry`, and entries grouped by category, each showing how many scenes use it. Click an entry to highlight those scenes; drag it onto a scene to link it.
- **Board:** Act → Chapter (columns) → Scene (cards). Acts collapse. Chapter columns are `--column-width` wide and **wrap onto multiple rows** inside an act. Chapters are numbered continuously across acts; scenes are numbered within their chapter.
- **Scene card:** a header (grip, `Scene n`, labels, edit and more), the scene's title (its Write gutter subtitle, edited in place, `Untitled` while empty), an editable summary with inline Codex mentions, linked Codex chips, then `+ Codex`, `Label` and the words already written in Write.
- **Acts:** `+ New Act` (toolbar, and the dashed `+ New act` at the foot of the board) adds an untitled act holding one chapter with one empty scene, and puts the caret in its title (`Name this act`). Each act's split button is `+ New Chapter | ✎ | ⋯`: ✎ renames the act in place, and ⋯ offers Expand/Collapse act and `Delete act`. Delete takes the act, its chapters and scenes off the board with Undo in the toast; a book always keeps one act.
- **Scope:** the book bar's `Scope` narrows the board and the Outline table to the full manuscript, one act or one chapter (acts keep their numbers), and the word, page and read-time counts add up what is in scope.
- **Reorder:** drag the ⠿ grip (shown on hover) or press Alt+arrow keys while a grip has focus. An accent drop line shows where it will land. Everything renumbers, and chapter references (`ch:slug`, #4) do not change.
- **Inline editing:** click any title or summary to edit it in place. Enter commits a title; Esc leaves. Changes sync 3s after the first edit and straight away on blur. The save status shows Unsaved (warn), Saving… (accent) and Saved (ok).
- **Codex mentions:** typing `@` in a summary opens the Codex picker and inserts a chip in the entry's category colour.
- **Labels:** user-defined, each a dot in a semantic colour (`ok`, `info`, `warn`, `danger`) plus a name.
- **Outline view:** a Board/Outline segmented control, mirroring Library Grid/List. Outline is a dense table with a group row per act, a row per chapter and a row per scene.
- **Series Knowledge base:** in a series book the sidebar shows the series-level categories under a `From <series>` note. Editing a series entry changes it for every book in the series. Series labels show `Series` in the label picker.
- **New book** (`?book=new&title=…`): one empty act and `+ New Chapter`. The Knowledge base is empty and offers `New Entry`, or shows the series' categories when the book is in one.
- **Import summary:** after an import, a dismissible info banner at the top of the board lists what came across (acts, chapters, scenes, words, entries) with `Undo import`.
- **Archive scene:** card ⋯ → `Archive scene` takes the card off the board, renumbers its chapter and archives its source uses. The toast names the uses archived and offers Undo, and the References badge updates. `Archived (n)` in the toolbar lists archived scenes with Restore, and Outline view shows them as a muted group.
- **Knowledge base entry panel** (`--panel-width`, the References detail panel's look; a sheet below 860px): the category square, the name (edit in place) and close; Category, Aliases (chips, Enter adds), Summary and **Always in context** (sent with every generation); **Used in** (`Chapter n · Scene n` and the summary; click to go there); **Additions** in book order; `Delete entry`, with Undo. It opens from the ✎ on an entry row (shown on hover), from `New Entry` (create mode) and from `#entry=<id>`. Clicking the row itself still highlights. Esc closes it. Write uses the same panel.

## Write screen patterns

`screens/write.html` defines these patterns. It uses the same book chrome and Knowledge base sidebar as Plan, with the **Write** tab selected.

- **Layout:** a toolbar (previous/next chapter, a chapter jump menu, the current act and scene, a Codex highlight chip, find), then the manuscript, then a **minimap** `--minimap-width` wide on the right edge.
- **Manuscript:** one continuous document, chapter after chapter, with an act marker wherever a new act starts. Each scene is a row: prose in a `--prose-width` column, then a **scene gutter** `--gutter-width` wide. Scenes are separated by a ◇ divider, and hovering it shows `New scene here`. Prose is `--text-md` at `--leading-prose`. When the document is narrower than 760px, the gutter moves above its scene.
- **Chapter header:** `Chapter n` overline, an editable title at `--text-lg`, and in the gutter the scene and word counts, a copyable `ch:slug` and an Actions menu.
- **Scene gutter:** `Chapter n · Scene n`, labels, the scene summary (the same text as the Plan card, editable here), linked Codex chips, then `Label`, `+ Codex` and the word count. It is sticky, so it stays in view while you write a long scene.
- **Blocks inside a scene** (the schema in #10): free prose, **Scene Beat** cards and **Codex Addition** cards. Beat and Codex Addition cards have a ⠿ grip. **Drag** the grip to reorder the card within its scene, or drop it into any scene in any chapter. An accent drop line labelled `Chapter n · Scene n` shows where it will land. Dragging near the top or bottom edge scrolls the manuscript, and dragging over the minimap jumps through the book. A beat takes its prose with it. A scene left empty gets a fresh prose block, and an empty prose placeholder in the target scene is removed. Alt+↑/↓ on a grip does the same from the keyboard and crosses scene and chapter boundaries at the ends. A move to another scene can be undone.
- **Scene Beat card:** `Scene beat` in accent, an optional title, Hide, then the instruction (with `@` mentions), a 200/400/600/custom length control, `+ Context` (Codex entries sent to the model for this beat), and a split button: **Generate prose** plus **template · model**. The model picker shows prompt templates beside the models. Ctrl+Enter generates. The beat's prose sits under the card. A hidden beat shrinks to a dashed one-line row, and its prose stays visible.
- **AI draft:** a tinted panel under the beat. It streams with a caret and a Stop button, then offers **Apply** (primary), **Retry** and **Discard**, with the model, word count and attempt number. If the beat already has prose, the panel says how many words Apply replaces and that the old text is kept in history. Apply and Discard can be undone.
- **Codex Addition card:** a left border in the entry's category colour, an entry chip you can change, and the text that holds from this point on.
- **`/` command menu:** opens at the caret in prose, with filter, arrow keys and Enter. AI: Scene beat, Continue writing. Codex: Codex addition, Mention entry. Insert: Chapter reference, Source reference, Split scene here (the text below the caret becomes the next scene; labels and Knowledge base links are copied, and the beats, additions and source uses below move with it). Formatting: Block quote. Inserting a block splits the prose at the caret's paragraph.
- **Inline marks:**
  - A Codex **mention** is a chip with a category-colour underline.
  - Codex names typed as plain text get a **dotted underline** in the category colour. Ctrl/Cmd+click opens them.
  - A **chapter reference** (`§ Chapter 7`) stores `ch:slug` and works out its number, so it survives reorders (#4). A target in a deleted act shows *Missing chapter* in danger; a deleted chapter shows its title in an archived style (tooltip *This chapter is archived*), and clicking it opens Plan's Archived list at that chapter. The reference keeps its `§ Chapter n` text and carries the chapter title as its tooltip.
  - A **source reference** (#2) is a small superscript number coloured by status: ok cleared, warn needs check, danger copyright risk. Numbers follow the order in the book.
  - Clicking any of these opens a card with its details and actions.
- **Minimap:** a mark per chapter and a tick per scene, sized to the scene. Empty scenes are hollow, scenes with a pending AI draft are accent, and scenes using the highlighted entry are accent. A viewport box shows the visible part. Click or drag to jump.
- **Knowledge base in Write:** clicking an entry highlights it in the text and gutters, and the toolbar chip steps through the scenes that use it. Drag an entry into the text to mention it, or onto a gutter to link it to that scene.
- **Scope:** the bookbar scope selector narrows the document to an act or a chapter, and the word, page and read-time counts follow it.
- **Format** (popover): text width (narrow / medium / wide, from `--prose-width`), spaced or indented paragraphs, show or hide beats, show or hide summaries, underline Codex names or leave them plain. **Focus** hides everything but the prose and fades the bookbar. Esc leaves it.
- **Preview** (Format → Preview, or Ctrl+Alt+P; remembered in this browser): a split pane right of the minimap with Quick preview of the scene or chapter in scope (for an act or the whole book, the chapter being read) in the book's template, on paper-white pages in both themes, fitted to the pane's width. The header has the template picker and ×; under it the scope, *≈ n pages*, *Updating…* while it re-pages, and **Open in Layout**. It follows the prose by scene (the pane jumps to the scene's first page), a click on a page shows that scene in the prose, and a save re-pages it in place without moving it. A template without `preview.css` shows the house-style notice; a server without pandoc says so in the pane. Focus hides it.
- **Autosave** works the same as in Plan.
- **Your access (#80):** with the view or comment role, a quiet chip sits where the save status was: **View only** or **Comment only**, with an icon and a tooltip saying why typing does nothing (a click shows it as a toast, for touch). Below 720px it keeps only the icon. The prose, beats, gutters, chapter titles and entry panel are not editable, the controls that change things are hidden (grips, New scene, beat length, context and Generate, Apply, Retry and Discard, Label, + Codex, chip ×, the ⋯ menus, New Entry, Delete entry, aliases), and pending AI drafts are hidden, since they belong to whoever ran them. Find, Format, Focus, highlight and every link keep working. When the role changes in an open tab, it switches without a reload and a toast says so (*Joel Dickson changed your access to Can view. This tab is read-only now.*). `?role=` previews a role and the tab links keep it.
- **Source markers** use the same ids, statuses and numbers as References: order of first use in the book, counting a pending AI draft's markers.
- **New source:** `/` → Source reference → **New source…** opens References' Add source with `?return=<n.m>&sel=<selection>`. Save comes back to `#scene=…&sel=…&cite=<id>&title=…`: the marker goes at the end of the saved selection in warn, later markers renumber, and a toast says *Cited <title>* with Undo. Cancel comes back to the scene.
- **Knowledge base entry panel:** the same panel as Plan. It also opens on Ctrl/Cmd+click on a mention or alias match, and **Used in** scrolls the manuscript to the scene. Renames and new aliases update the alias underlines straight away.

## References screen patterns

`screens/references.html` defines these patterns. It uses the same book chrome as Plan and Write. **References** is a book-level section, so it sits after a divider following the Plan · Write · Chat · Review tabs, with a count badge: danger for copyright risks, otherwise warn for sources to check. The Knowledge base sidebar starts closed here. Clicking an entry shows only the sources linked to it.

- **Clearance status** for each source is worked out from its checks, never set by hand: **Copyright risk** (danger) when a use needs permission that hasn't been granted, **Needs check** (warn) when a check warns, the source is ready to sign off, or it has new uses since sign-off, **Cleared** (ok) once signed off, and **Not cited** (muted) when the book has no marker for it. The colours match the source-reference markers in Write.
- **Summary strip:** a stacked meter by status, `n of m cited sources cleared`, whether risks block print export (#13), status filter chips with counts, and the unflagged-quotes button.
- **Source table** (the Library list view pattern): the marker number (order of first use in the book, the same number Write shows), the source (title, then author · year · publisher), kind, where it's used (`2 uses · Ch 4, 8`), quoted words with a bar against the limit, licence, and the status with its reason. Groups are Status (risk first), Chapter of first use, Kind or None. Columns drop as the screen narrows: kind and licence first, then quoted words, then uses.
- **Detail panel** (`--panel-width`, a sheet over the list below 860px), top to bottom:
  - **Clearance:** a verdict (status, reason, one next action), the permission tracker when permission is needed, and the checklist. The checks are prose quoted against the limit, lyrics and poetry, figures, data, licence, citation complete, and identifiers verified. A footer names the publisher rules in use and says the checks are a guide, not legal advice.
  - **Permission tracker:** Drafted → Sent → Granted or Refused. The request letter is drafted from the uses (words, pages, chapters) and can be edited. A grant attaches the letter and adds a credit line to the citation.
  - **Sign-off** records who cleared the source and when, and any new use reopens it.
  - **Used in the book:** each passage under `Chapter n · Scene n`, with the used words highlighted in the use type's colour (paraphrase gets a dotted underline instead), the marker, a use-type chip you can change (Quote, Paraphrase, Data, Figure, Lyric), Open in Write and, for quotes, Paraphrase with AI.
  - **Source details:** fields you edit in place. Required fields for the kind show warn when empty, and ISBN, DOI and URL show Verified, Redirects or Not found, with Re-check.
  - **Citation** in the book's style (Chicago, APA or Harvard; a book setting shared with print), Copy, then **History**.
- **Publisher rules** (book settings, also opened from the checklist footer): prose words quoted from one source without permission (300 by default). Lyrics, poetry and figures always need permission unless the licence allows reuse. Changing a rule rechecks every source.
- **Unflagged quotes:** a scan on save finds text in quotation marks with no marker, and passages that match source text attached to a reference. Each one offers Cite *source*, Other source…, Not a quote, and Open in Write.
- **Bibliography view** (a Sources/Bibliography segmented control): a page preview in the chosen style, sorted by author, with uncited sources left out and still-risky ones underlined in danger. Export offers BibTeX, RIS, CSL JSON and a permissions log for the publisher.
- **Add source:** paste an ISBN, DOI or URL to look it up (web pages are archived), or enter it by hand. **Import** reads CSL JSON (a Zotero export), BibTeX or RIS and shows `n new · n already in References · n skipped` before it writes anything. A source's `⋯` menu has **Merge into…** (a duplicate's details and uses move to the source that stays).
- **Deep links:** `references.html#<id>` selects a source, and `#new` opens Add source, for Write's reference card and the `/` → Source reference picker.
- **Return to Write:** `?return=<ch.sc>&sel=…#new` adds a note to Add source ("Will return to Write · Chapter n · Scene n"), turns Look up into **Save** and adds **Cancel**. Save goes back to Write with `cite=<id>&title=<short title>`. With Add source closed, an accent bar in the summary strip offers **Cite *source* and return** and Cancel.
- **Duplicate check:** an ISBN, DOI, URL or title that's already in References shows an "Already in References" card, and the primary action becomes **Use existing source: *title***.
- **Links into Write:** Open in Write goes to `write.html#scene=<ch>.<sc>&ref=<id>` (unflagged quotes: `#scene=` only). Paraphrase with AI and Paraphrase instead add `&paraphrase=1`; Paraphrase instead picks the smallest quote that brings the source back under the limit.
- **Columns with the sidebar open:** kind and licence drop below 1560px, and quoted words below 1280px.

## Moving between screens

These rules hold on every screen (#16). Each screen is still a self-contained file.

- **Which book:** book screens take `?book=<id>` (ids from the Library catalogue; none means Product Engineering, the only book with full content). The bookbar shows that book's title, author and cover, and every tab link keeps `?book=`.
- **Tabs:** `Plan · Write · Chat · Review | References` on every book screen, References after a divider with its count badge.
- **Back (←)** is a link: to `library.html#series=<id>` for a book in a series, otherwise to `library.html`. Its label says which.
- **Last screen:** each book screen records itself in `localStorage['codex.last.<book>']`, and Library opens the book there (Plan for a new book).
- **Deep links** are hash parameters, `#key=value&key2=value2`, with scenes and chapters addressed by their display numbers: `#scene=5.2`, `#chapter=5`, `#kb=<entry>` (highlight), `#entry=<entry>` (entry panel), and on Write `&ref=<source>` (opens that marker's card). References also keeps `#<source>` and `#new`. The target scrolls into view and flashes. Every Open in Plan, Open in Write and Open in References is a link built from these.
- **Highlight carries over:** the highlighted Knowledge base entry is kept per book in `sessionStorage['codex.hl.<book>']`, so Plan, Write and References (as its entry filter) open with it already on. A `kb` in the URL wins.

## Knowledge base patterns

`screens/codex.html` defines these patterns. The Knowledge base sidebar is the one Plan and Write use. Clicking an entry, `New Entry`, the `+` on a category heading, or a Codex mention or chip in the book opens the **entry window**. The manuscript behind it is a static stand-in for Write.

- **Entry window:** `--overlay-width` wide, centred over the main area with a scrim behind it. The sidebar stays usable, so clicking another entry switches the window to it, and clicking the open entry closes it. A 3px bar along the top is in the category colour. **Expand** fills the main area, with the content column at `--prose-width`. Below 720px the window takes the whole screen. Esc closes it, and Alt+↑/↓ (or the arrows in the header) step through the entries in sidebar order. The selected tab stays put while you step, so you can check Used in for each entry in turn.
- **Header:** the category chip (change it, or create a category with a name and one of the `--category-*` colours), the position (`5 of 12`), previous and next, Expand, ⋯ (Copy reference, Duplicate, Delete) and Close. The name is edited in place. **Aliases** are the other names that count as this entry in the text: they drive Write's dotted underlines and the Name in text matches.
- **Reference id:** an entry is stored as `e:<slug>`, taken from its first name and never changed after that, so mentions survive a rename (the same idea as `ch:slug`, #4). The id shows beside the tabs with a copy button.
- **Entry tab:** a **Summary** of one or two lines, shown on cards and sent as short context, then **Content**: long-form text with headings, quotes, lists and `@` mentions of other entries, with a word count. A new entry with no content offers **Import from URL**, which fills Content and the URL field.
- **Used in tab:** every scene that touches the entry, grouped by chapter, with a tally by kind and **Highlight in Write**. Each scene shows chips for how it uses the entry (Mention, Summary, Linked, Beat, Beat context, Timeline, and Name in text when the name is plain text), the sentence that shows it in use, **Open in Write**, **Unlink** for a linked scene, and **Make mention** to turn the first plain-text use into a mention.
- **Timeline tab:** it is always the same entry. Timeline notes are facts that hold from a point in the book onward (Write's **Codex Additions**), listed in book order after *Start of book*. Edit a note in place, open it in Write, remove it, or **Add a note at…** any scene, which adds a Codex Addition at the start of that scene. A draft for a scene gets the entry plus every note up to that scene.
- **Rail** (`--gutter-width`, below the content when the window is under 680px wide): **Details** are fields set by the category (Blog Posts: URL, Published; Laws: Coined by, Year; Stories: When, Where; Research: Authors, Year; People: Role, Known for) plus custom fields added with `+ Field`. **Source** links a source in References (#2), with its clearance status and Open in References. **Related** links entries both ways. Then the created and edited dates.
- **New entry:** opens on an empty entry in the chosen category with the name focused. Enter moves to the summary. A new entry left completely empty is discarded on close.
- **Delete** says how many scenes use the entry. Mentions become plain text, links and beat context are removed, and its timeline notes are deleted. It can be undone from the toast, as can the window's other button actions (category, aliases, links, Make mention, timeline notes).
- **Autosave** works the same as in Plan. **Deep links:** `codex.html#<id>` opens an entry and `#new` starts one.
- **Scope** is per book in v1, so the window shows no scope control. Per series and global entries come later.

## Layout screen patterns

`screens/print.html` defines these patterns. It uses the same book chrome, with **Layout** after References past the divider. Its badge counts the issues that block export (danger). The reference always shows the Players Guide, because the print pipeline comes from that book; only Chapters 3 and 4 have text.

- **One source, many layouts:** the pages are built from the same prose blocks and directives as the print build (`::image`, `:::readaloud`, `:::sidebar`, `::spell`, `::statblock`, pipe tables). Changing the template or an option re-flows the pages and never changes the text.
- **Toolbar:** what to preview (Front matter, a chapter, or a scene, following the bookbar scope), a **Quick / Proof** segmented control, the template picker (thumbnail, short name, pinned version), trim size, then **Export for printer…** as the primary action.
- **Page canvas:** pages on `--color-bg`, as spreads (verso left, recto right, a first recto page alone) or single pages. Fit width or a fixed zoom, where 100% means actual size. A page rail of thumbnails sits on the left, with a warn dot on pages that have print issues. A status bar shows Quick (live, updated n ago) or Proof (exact page count, rendered n ago, cached), the current page, and Single/Spread.
- **Quick preview** paginates in the browser using the template's `preview.css`. Page breaks are close, not exact. An edit in Write re-renders within a few seconds and flashes the changed block. A template without `preview.css` falls back to a neutral **house style**, with a warn banner pointing to Proof.
- **Proof** compiles one chapter with the real LaTeX template and 150 dpi proxy images. It shows the steps while rendering, then the pages with a banner: *chapter only, no contents or cross-references*, the template version, Download, Log and Re-render. Overfull lines get LaTeX's black margin mark. Proofs are cached by chapter content, template version, trim and options; any change makes the proof out of date, and you can show the old one or re-render. Front matter can't be proofed on its own, because it needs the whole book.
- **Print issues on the page** (UI marks, never printed, toggled by *Print issues*): a warn flag with the effective dpi on low-resolution images, and a hatched strip where a raw LaTeX block is skipped.
- **Blocks:** hovering outlines a block and labels its `Ch n · Sc n`. Clicking opens a card: for an image, the asset, its pixel size, placed size and **effective dpi** for this template and trim, plus Column / Full page placement; for a spell or stat block, the Knowledge base entry it prints from; for raw LaTeX, **Convert to ::aside**. Every card has Open in Write.
- **Panel** (`--panel-width`, a sheet below 980px), three tabs:
  - **Template:** the template card (kind, engine, pinned version), an upgrade notice listing what changes, with **Preview v…** (a banner then offers Keep or Apply, and Apply can be undone), and a hint when there is no `preview.css`. Then **Options** generated from the template's schema as small segmented controls, with trim size first; the **Package** file list; and Fork, Edit files or Upload.
  - **Preflight:** a verdict (*n issues block export* or *Ready to export*), then **Blocks export** (danger), **Warnings** (warn) and **Notes** (info). Each item has its location, Show on page, Open in Write and a fix where there is one. Image dpi is worked out for the current template, trim and columns, so switching to one column can add warnings. Copyright risks come from References.
  - **Exports:** a running job (steps, progress, Cancel; it carries on after a reload), past exports with their settings and template version (Download, Export again with these settings, and the log for a failed one), then cached proofs.
- **Export for printer** (dialog): the book, the pinned template, trim, bleed (None, 3 mm, 0.125 in), crop marks (only with bleed), image quality (Print 300 dpi or Screen 150 dpi), and the format (PDF). It ends with a preflight summary. Blocking issues disable Queue export unless you choose to **export a draft** with DRAFT across every page. The footer gives estimated size, pages and time.
- **Template thumbnails:** a tiny page drawn in the template's look (`.tth`), used in the picker, the toolbar and the template card.

## Book settings patterns

`screens/settings.html` defines these patterns. ⚙ in the bookbar of every book screen links to `settings.html?book=<id>`. It uses the same book chrome with no tab selected and ⚙ shown as current. It is never the screen a book opens on, so it doesn't write `codex.last.<book>`.

- **Layout:** a sticky section nav (Book, Series, Writing, Citations & permissions, Layout & print, Sharing, Archive & export) beside one column of section cards, at most 760px wide. The nav follows the scroll, and below 860px it becomes a scrolling strip above the cards. Each section is a deep link: `#book`, `#series`, `#writing`, `#citations` (with `#rules` and `#letters` inside it), `#layout`, `#sharing`, `#archive`. Sharing sits just before Archive & export, so the owner-only cards are together and the danger card stays last. The target flashes, and `#rules` focuses the word limit.
- **Field rows:** label on the left (168px), the control, then help text under it in `--text-xs`. Rows are split by dashed lines. Below 640px the label goes above the control.
- **Autosave** works as in Plan: Unsaved, then Saving… 3s after the first edit or straight away on blur, a choice or a toggle. There is no Save button. Changes with wide effects say what they did in a toast, with Undo where it can be undone.
- **Book:** title, author (as printed; a pen name is fine), status (the Library status dots as a segmented control), target words with the words ÷ target bar, and the cover.
- **Series:** the series select and the number (`Book 003 · before Hollow Throne`), then the series order with this book highlighted and `was 003` beside books whose number changes. Published books that would renumber are marked in warn. A number change inside the same series applies at once, with Undo.
- **Moving between series asks first.** Picking another series (or None) shows a *Not moved yet* note with **Review move…**. The dialog shows From → To and each step of the copy-down in #10: copy the old series' categories, entries and labels onto the book, repoint the book's links (including References' entry links), keep the publication settings it inherited, join the new series (same-named categories and labels merge), renumber the other books, and a note that the old series and its other books don't change. A warn note says moving back won't merge the copies again.
- **Writing:** the style guide, with a word count. In a series the series guide is shown under it, read-only, marked **Series**: both are sent with every AI draft.
- **Series values and book overrides** (`publication_settings`, the book's values win): in a series book each citation and permission value has a chip after its label. **Series** (muted) means it comes from the series. Changing it makes it **This book ×** (accent); clicking that goes back to the series value, with Undo. Setting a value equal to the series value also goes back to inheriting.
- **Citation style:** Chicago, APA or Harvard, with an in-text example and two bibliography entries that change as you pick.
- **Publisher rules:** the prose word limit, with its effect on References worked out live: a strip of each source's quoted words against the limit (danger above it), the sources at risk and why, and how many block print export. Lyrics and poetry (always ask) and figures (ask unless licensed) are fixed rules, shown as statuses. The References badge and the nav badge follow the limit.
- **Permission letters:** publisher (blank means you publish it yourself), year, formats (check chips), first print run, territory and language, then the sentence every drafted request will use, with the values highlighted and missing ones in warn. Requests already sent keep their wording.
- **Layout & print:** the template (with its thumbnail, pinned version and any newer version), trim sizes the template supports, and whether anything blocks print export, linking to References. Template options, preflight and exports stay on Layout.
- **Sharing (#80):** the owner first (*You · Owner*, a lock, never removable), then one row per person: avatar, name, email, a **Can view / Can comment / Can edit** menu and **Remove**. A change saves straight away with an Undo toast. A book in a series has two lists, **This book** (*People who see <book> and nothing else in the series.*) and **Whole series: <series>** (every book, including later ones, plus the series' Knowledge base, labels and style guide), each with its own Add people field. A row whose book grant is covered by the series says so (*Can edit through the series*). The nav shows how many people besides the owner have access.
- **Add people:** one email field (*Type their whole email address. Codex only finds an exact match: there’s no search and no suggestions.*). Nothing is looked up or shown until it holds a whole address; then one lookup runs 400ms after typing stops (*Looking up…*). Case and surrounding spaces are ignored and nothing else, so `ana@example.co` doesn't find `ana@example.com`, and a disabled account is no match. A match shows the person (name, email) with a role menu set to Can view and **Add** (Enter adds); otherwise *No Codex user has that email.* It also says *That’s you. You own this book.*, *<name> already has <role> on this book. Change it in the list above.*, and, in This book, either *<name> can already edit every book in <series>. A grant on one book can only add access.* or a note that roles at or below their series role are disabled.
- **Roles on this page:** people who aren't the owner see Sharing read-only: names and roles, no emails, their own row marked **You**. **Editors** change everything else, but moving the book, its number in the series, *Published* (and every status once published), Duplicate and Archive are disabled with the reason as the tooltip and a line under the series select. **Viewers and commenters** get a note at the top (*View only. <owner> shared <book> with you to read…*), every field and button disabled, and the **View only** / **Comment only** chip from Write in place of the save status. `?role=owner|write|comment|view` and the Preview panel's *View as* switch between them.
- **Moving and archiving say who is affected:** the move dialog adds *3 people with access to Forsaken Gods will be able to see this book* (names and roles under it) and, when leaving a series, *n people with access to <series> will no longer see this book* (people shared on the book itself keep it). Archiving says the people it's shared with directly lose access and Restore doesn't share it again.
- **Archive & export:** Duplicate (copies everything except References, since clearance covers one book's print run), Export source (.zip of Markdown with directives, plus the Knowledge base and References as JSON) and Archive (hidden from Library and ⌘K, nothing deleted, keeps its number in its series; a warn bar offers Restore).

## Mobile screen patterns

`screens/mobile.html` defines these patterns for the Expo app (#35). It draws each screen in a 390pt phone frame at `data-density="touch"`. Only Library, Plan, Write, Knowledge base and Book settings come to mobile; Chat, Review, References, Layout, the Plan board, Import, Series settings and ⌘K stay on desktop.

- **Sign in:** the first screen on a fresh install and after Sign out; no tab bar or book bar. The Codex mark, *Sign in to Codex*, then **Server**, **Email** and **Password** fields and a full-width **Sign in**, with *No account? Ask your Codex admin.* under it. Codex is self-hosted, so the server address comes first: `https://` is added when no scheme is typed, and on leaving the field the app calls the anonymous `GET /api/health`, showing *Codex <version> · connected* in ok or *Can't reach <host>…* in danger under the field. Sign in stays disabled until that check passes. A refused sign-in shows the desktop message (*Incorrect email or password, or the account is locked for now.*) as a danger note above the button. The token goes in the device keychain, so the screen is not seen again until Sign out. The avatar in Library opens the **Account** sheet: name, email, the server and its version, and **Sign out** (danger), which returns to Sign in with the server filled in.
- **Navigation:** Library is the root screen and has no tab bar. Inside a book a bottom tab bar (`--tab-height` plus the home-indicator inset) holds **Plan · Write · Knowledge · Settings**, each acting on the open book. The selected tab has an accent-soft pill behind an accent icon. Pushed screens (an entry, the style guide) keep their parent tab selected. The tab bar hides while the keyboard is up.
- **Book bar:** ‹ back to Library, the cover, title and `Book n · Series`, a ⌄ that opens the **book switcher** sheet (recent books, then *All books in Library*), the save-status dot and ⋯. A pushed screen has a bar with `‹ Parent`, a centred title and an optional action (`Done`).
- **Detail opens as a sheet or a push.** Short edits (a scene, recording, the chapter jump, the book switcher) open as a bottom sheet over a dimmed screen with a grab handle and ×; a sheet with actions ends in a dock of two buttons, the primary on the right. Long content (an entry, a long text field) pushes a screen. Back is always one level up.
- **Library:** a 28px large title and search, a **Continue** card for the book last opened (on the screen last used in it, `codex.last.<id>`), then groups per series and *Standalone*. A row is a cover at `--cover-width`, `Book 003` overline in a series, title, `words / target · edited`, a 3px progress bar and the status. Series are groups, not a separate screen.
- **Plan:** outline only, no board or drag. A scope pill and the word, page and read-time counts sit under the book bar. Act headers stick to the top and collapse; chapters are headings; scenes are cards with number, title (`Untitled` in italic muted), a two-line summary, labels, Knowledge base chips, additions and words. Tapping a scene opens its sheet: title, summary, labels and entries edit in place and autosave as on desktop, with **Open in Write** and **Record**.
- **Write:** one column of prose at `--text-md` / `--leading-prose`. The scene gutter sits above its scene as a tappable card (`Scene n`, labels, words, summary, chips) that opens the scene sheet; the scene card of a scene you are not reading collapses to one line. A chapter pill with ‹ › replaces the chapter menu and the minimap, and opens the **chapter jump** sheet grouped by act. Tapping the prose edits it: the existing TipTap editor in a WebView (#35), with the tab bar hidden and an accessory bar above the keyboard holding `/` (the command menu), `@` (mention), **Beat**, ◇ (new scene), **B**, *I*, ❝ and ⌄ (close the keyboard). Undo and redo join the chapter pill. Scene beats show their instruction, length, `+ Context` and **Generate prose** as on desktop.
- **Knowledge base:** the desktop sidebar as a full screen. Search and `+`, then category chips in a scrolling strip (All, each category with its count, *Voice notes*, *Unused*) that replace the funnel filter. A series book shows the *From <series>* note. Rows: the category square, name, `Always` tag, one-line summary, scene count and voice-note count; a `+` on each category heading starts an entry there.
- **Entry screen:** category chip, name, aliases (`+ Alias`), summary, **Always in context** as a switch, **Voice notes**, **Used in** (`Chapter n · Scene n` and the summary, tap to go there) and **Additions**. A dock holds **Scenes** and **Record to entry** (primary).
- **Recording (#33)** starts only from a scene sheet or an entry, so it always has a target. The sheet shows the target, a timer, a live waveform and a live transcript, then a choice of what happens on stop (from a scene: *New entry* or *Add to an entry*; from an entry: *Add to entry* or *Keep as note*), with Pause, Stop (danger) and Discard. Whether transcription runs on the phone or the server is a setting, not a per-recording choice. A recording lands on the entry as a voice note; its transcript becomes an Addition or the summary.
- **Book settings:** grouped rows in the desktop order (Book, Series, Writing, Citations & permissions, Layout & print, Archive & export): label, value, ›. Values from the series carry the **Series** chip. Long text (the style guide) pushes an editor with `Done`. Layout & print shows its template with a *Desktop* marker and does not open; Archive book is in danger.

## Cross-cutting rules

What happens to the things that point at something when that something changes (#16 review, section C; #23 Q11). The proposed rules R1-R7 and the journeys that pin them are in `docs/journeys-wave5.md` (branch `feat/16-finish`); this table says what the app does today and which test pins it. **Built** is the behaviour now; **(proposed, confirm)** is a default nobody has confirmed (#23 W5.0 asks Joel). Where the operation or the rule is not built, the wave-5 lane owns the build and its test; nothing here builds it.

| # | Operation | Rule today / proposed | Status | Test or owner |
|---|---|---|---|---|
| 1 (R1) | Chapter that `[Title](chapter:<id>)` links point to is archived | Built: the prose is never rewritten; the link keeps its id. **Delete chapter** (chapter ⋯ in Plan) archives one chapter; the outline keeps it as archived with its title, and Write draws the link as that title in an archived style (tooltip *This chapter is archived*) that opens Plan with the *Archived* list open at the chapter, where **Restore** brings it back. Archiving the whole act still drops its chapters from the outline, so a link into a deleted act reads **Missing chapter** until the act is restored. A reorder changes the live label (`§ Chapter 5`), never the Markdown. | Built (J16 step 9) | `ChapterLinkRuleTests`, `WriteReadTests`, `J16_RestructureBeyondReorder` |
| 2 (R2) | Delete a KB entry with mentions, `scene_kb`, `beat_kb`, additions | Convert, not block: mentions become plain text, links and context are removed, notes and their `::kb-addition` lines are deleted, the entry is archived so Undo works. | Built; documented only here | `KbDeleteEndpointTests` (existing); `J21_EditAndMaintainAKbEntry` step 7 (delete, Undo) |
| 3 (R3) | Move a scene to another chapter | Beats, KB links, additions, labels and source uses are keyed by scene id and travel with it; prose and `chapter:` links are untouched; marker numbers follow reading order; the move is never blocked. Drag the card onto another chapter, or card ⋯ → **Move to chapter…**. An emptied chapter is kept. | Built (J16 steps 4-5) | `PlanMoveTests`, `J16_RestructureBeyondReorder` |
| 4 (R4) | Delete a source that has uses | Convert, not block: `Remove source` (`DELETE /api/references/{id}`, the same as `POST …/archive`) turns every marker into plain text with a revision cut per changed scene (so a restore can undo it), archives the uses and the source, clears the suggested source of open quote flags, and drops the source from the table, the bibliography and the exports. Nothing is hard-deleted. | Built (L19.1) | `SourceArchiveTests`, `SourceWithUsesRuleTests`; J24 step 8 |
| 5 (R5) | Archive a scene holding the only use of a source | The source becomes **Not cited** (no number, no uses). It leaves the cited bibliography but stays in the sources table and the exports.
