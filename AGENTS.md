# Codex

A novel-writing app. The screens, their routes and how they link together are in `docs/navigation.md`.

**UI work** (any screen, component, colour, spacing or theming): read `design/README.md` first. It covers the design tokens (`design/tokens.css`) and the reference screens (`design/screens/`).

## Behavioural norms

- **Don't assume.** Don't hide confusion. Surface tradeoffs and ask before guessing.
- **Simplicity first.** Minimum code that solves the problem. Nothing speculative.
- **Surgical changes.** Touch only what you must. Clean up only your own mess.
- **Goal-driven execution.** Define success criteria up front. Loop until verified.

## Where things are

- Docs: `docs/auth.md` (sign-in, the access rule and sharing, users, test sign-in), `docs/navigation.md` (screens, routes, deep links, slot API), `docs/testing.md` (test conventions, harness, banned list), `docs/prose-format.md` (prose Markdown), `docs/ai-drafts.md` (drafts and the user's AI integration), `docs/events.md` (event bridge), `docs/mcp.md` (MCP server: stdio, `/mcp`, tools, errors). Telemetry: `docs/observability.md`.
- **Test ids:** selectors are `data-testid` only. The shell's ids are in `src/Codex.Client/src/testIds.ts` and `src/Codex.TestSupport/TestIds.cs` (kept identical; `TestIdRegistryTests` pins them). A lane never adds ids there: it keeps its own in `features/<area>/testIds.ts` (and its own C# `TestIds` file) with its prefix (`library-`, `plan-`, `write-`, `kb-`, `refs-`, `settings-`).
- **Errors:** every endpoint returns `ApiError { error, code }` (`Codex.Contracts.Errors`; TS `@codex/core/api/apiError`). Throw `ApiException.NotFound(...)` / `Conflict` / `Validation` / `Ambiguous` / `OutOfScope` / `Blocked` / `NeedsConfirmation` / `NotConfigured` / `Unauthorized` / `Forbidden` / `RateLimited`; `ApiErrorServices` maps the code to the status (not_found 404, conflict 409, validation 400, ambiguous 409, out_of_scope 422, blocked 422, needs_confirmation 409, not_configured 503, unauthorized 401, forbidden 403, rate_limited 429, internal_error 500). Any other (unhandled) exception becomes `internal_error` 500 with a fixed message. Framework errors under `/api` get the same body: no endpoint matched (404 `not_found`), a binding failure such as malformed JSON (400 `validation`; the message is the framework's), a bodiless 401/403 (`unauthorized`/`forbidden`), any other bodiless 4xx (`validation`, status kept). Never build error bodies by hand. TS: `@codex/core/api/client` throws `ApiRequestError { status, code }`.
- **Prose:** `IProseStore` (`Codex.Contracts.Manuscript`; `ProseStore` in `Features/Manuscript`) is the only server-side writer of `prose.body`: `UpdateAsync(sceneId, edit, expectedVersion, origin)` locks the scene, 409s a stale version, cuts the revision and publishes `ProseSaved`; version 0 means no prose row yet. `UpdateManyAsync` edits several scenes in one transaction; both take `ProseWriteOptions` (`GenerationId` tags the revision; `BeforeWrites` runs a feature's own SQL first in the same transaction, e.g. inserting the beat, addition or reference use a new body points at; `InTransaction` runs after the prose rows are written), so a command that changes prose and its own rows is one transaction from any feature. Two readers, which agree by `docs/prose-format.md` → *Reader rules*: `src/prose` (TS parser, serializer, `ProseEditor`, `SummaryEditor`) and `Codex.Application.Prose.ProseDocument` (C# edits: insert after a beat, wrap/unwrap `ref:`, make or remove a `kb:` mention, strip `::kb-addition`, list embeds).
- **Editing utilities** (`src/editing/`; `AutosaveController`, the save-status store and the toast store live in the core's `editing/`): `useAutosave` (3 s / blur / version / 409) and the one save-status store with `SaveStatus` (fill the book bar's `saveStatus` slot), `LabelPicker`, `showToast({ message, undo })` (the shell mounts the one `ToastHost`).
- **Events:** `IBookEvents` (`Codex.Contracts.Events`) publishes `ProseSaved`, `StructureChanged`, `JobProgress`, `BookMetaChanged`, `AccessChanged` (sent only to the affected user's tabs); handlers run off the publishing request. TS mirror in `@codex/core/api/events`. Every process also NOTIFYs each event on Postgres channel `codex_book_events`; the web host listens and republishes other processes' events to its subscribers (`docs/events.md`). Keep events under 8000 bytes of JSON. The SignalR hub `/hubs/book` (`Codex.WebApi/Realtime`) relays them to the browser (`src/realtime/`); requests carry `X-Codex-Client` so a tab ignores its own events.
- **Seed:** `db/seed/01–09` (library, structure, KB, references, prose, layout, embeds, JD's dev password `codex-dev-password` and admin flag, and Ana (`ana@codex.local`, same password) with view on Product Engineering and write on the Forsaken Gods series) builds the #16 Part 1 data with fixed ids from `SeedIds`; its numbers are posted on #16. Timestamps are relative to load time; layout templates have no fixed ids (find them by slug).
- **Shared DTOs:** `LibraryDto`, `BookHeaderDto` (`Codex.Contracts.Books`; TS `@codex/core/api/types`); JSON fixtures in `src/Codex.TestSupport/Fixtures/` are round-tripped in C# and TS. JSON is camelCase (web defaults) for controllers and minimal APIs alike; a column whose values the schema fixes with a `CHECK (… IN (…))` travels as a `string` holding the stored value (`"needs_check"`), not a C# enum.
- **Dates and labels:** timestamps travel as ISO `DateTimeOffset` plus a server-formatted label. `Codex.Core.DisplayDate.Relative(value, timeProvider)` gives the Library's "just now / 12m ago / 2h ago / Yesterday / 30 Sep / 2 Mar 2025"; `DisplayDate.ShortDay` gives "19 Oct". Tests compute expected labels with the same functions and `TimeProvider.System` (D4).
- **Module scan:** features register services through `IServiceModule` and expose HTTP through controllers (both found by scan); `IEndpointModule` is only for non-MVC endpoints (the hub, `/mcp`, health). Never edit `Program.cs`.
- **Frozen files** (conductor only after wave 0): `src/Codex.slnx`, `Directory.Build.props`, `*.csproj`, `src/BannedSymbols.txt`, `.editorconfig`, Dockerfiles, `docker-compose.yml`, `.github/workflows/*`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `vite.config.ts`, `tsconfig.json`, `eslint.config.js`, `playwright-ct.config.ts`, `playwright/index.tsx`, `Program.cs`, `appsettings*.json`, `AGENTS.md`, `db/schema/*`, `db/seed/ids.csv`, `SeedIds.*`, `db/prose-corpus/*`. Need a package, project or analyzer change? Stop and report.
- **Banned patterns** (use the alternative): `WaitForTimeout`/sleeps (wait for a locator or response); `DateTime.Now`/`UtcNow`/`new Date()` for display (`TimeProvider`, server-provided values); `[Retry]`, `[Ignore]`, `NoWarn`, `#pragma warning disable`, `eslint-disable`, `@ts-ignore` (fix it); test-only branches or props in production (`ConfigureTestServices`, `page.route`, fixtures); non-`data-testid` selectors; string-built SQL (Dapper parameters); `DELETE FROM` in `src/` (soft-delete with `archived_at`; link rows too, and re-adding revives the row; derived tables exempt are listed in `NoHardDeletesTests`, #85); EF Core (Dapper); compensating for a wrong contract (stop and report); editing a frozen or another owner's file (stop and report); `--force`, `--amend`, `git reset --hard` on pushed history, pushing to `main`.

## Commands

**Test locally, and only what your change touches.** CI is slow: about 8 jobs per pull-request push. So:

- Verify on your machine before pushing, never by pushing and waiting for CI.
- Run the tests your change can affect, not the whole suite: the test classes for the code you changed (`--filter "FullyQualifiedName~<Class>"`), the API or acceptance namespace of your feature, and the component spec or vitest file next to your component.
- Run the whole suite only for a change with wide reach: shared contracts, `api/client.ts`, `test-support/`, the shell, the schema or seed, a CI workflow or a Dockerfile.
- Run the client's `format:check`, `lint` and `typecheck` whenever you touch the client, the core's when you touch `src/Codex.Core.Client` (the SPA and the mobile app typecheck the core's files they import, the core's own rules run only there; a core change runs the mobile checks too), and the mobile app's when you touch `src/Codex.Mobile`. Build Release whenever you touch C#. Both are cheap.
- Batch your work into few pushes: each push starts a full CI run and cancels the one in progress. Use CI as the final check, not the debugger.
- To diagnose a CI-only failure, read the job log and the uploaded Playwright report (`gh run download <run> -n playwright-report`), then reproduce it locally before pushing a fix.

Run `source ~/.local/codex-env.sh` first on the shared agent host (it puts .NET on PATH and sets `CODEX_TEST_DB`, a long-lived local Postgres; without `CODEX_TEST_DB` tests start a `postgres:18` Testcontainers container). Timings are warm, on the build host.

```bash
dotnet build src/Codex.slnx                                                     # ~3 s warm; warnings are errors
dotnet test src/Codex.UnitTest                                                  # ~3 s
dotnet test src/Codex.WebApi.Tests                                              # all API tests, ~6 s
dotnet test src/Codex.WebApi.Tests --filter "FullyQualifiedName~HealthTests"    # one class, ~6 s including build (~2 s with --no-build)
(cd src/Codex.Client && pnpm install && pnpm run build)                         # once, and after client changes: acceptance tests serve this bundle
dotnet test src/Codex.AcceptanceTests --filter "FullyQualifiedName~ShellSmokeTests"   # one acceptance test, ~8 s
dotnet test src/Codex.AcceptanceTests --filter "FullyQualifiedName~Codex.AcceptanceTests.Lanes.Plan."  # a CI shard; matching nothing passes
cd src/Codex.Client && pnpm run lint && pnpm run typecheck                      # ~2 s each
cd src/Codex.Client && pnpm test                                                # vitest, ~2 s
cd src/Codex.Client && pnpm run test-ct                                         # Playwright component tests, ~3 s
cd src/Codex.Client && pnpm run format:check                                    # CI runs it; `pnpm run format` fixes
cd src/Codex.Core.Client && pnpm run format:check && pnpm run lint && pnpm run typecheck && pnpm test   # the core, ~5 s
cd src/Codex.Mobile && pnpm run format:check && pnpm run lint && pnpm run typecheck && pnpm test && pnpm run test:screens && pnpm run bundle   # the mobile app, ~30 s
scripts/db-reset.sh [name]                                                      # dev database from db/ (PGHOST/PGPORT/PGUSER/PGPASSWORD)
dotnet run --project src/Codex.WebApi                                           # dev: Kestrel on :5688, CODEX_DB_CONNECTION from appsettings.Development.json
cd src/Codex.Client && pnpm run dev                                             # dev SPA on :3000, proxies /api and /hubs (ws) -> :5688
docker compose -f src/docker-compose.yml up --build                             # app + worker + postgres:18
```

Failed acceptance tests leave a Playwright trace in `artifacts/playwright-traces/` (open with `pnpm exec playwright show-trace <zip>`).

## Testing model (departs from the template)

- **A test class is one scenario on one database.** `ApiFixture` / `AcceptanceFixture` clone the `codex_seed_<hash>` template database (`CREATE DATABASE ... TEMPLATE`, under an advisory lock) in `[OneTimeSetUp]`, start their own Kestrel instance of the real app (`CodexHost`) against it, and drop the clone in `[OneTimeTearDown]`. Tests inside a class run in `[Order]`; independent scenarios are separate classes; classes run in parallel (`[assembly: Parallelizable(ParallelScope.Fixtures)]`). This replaces the template's one-app-per-run `[SetUpFixture]` on purpose. `CodexDatabase.CloneSchemaAsync()` gives a clone with no seed.
- Test databases use the `en_US.UTF-8` locale (`CodexDatabase.Locale`, the `postgres:18` image's default), whatever the server's default, so sorting and `[[:alnum:]]` behave as in production.
- Template databases are named by a hash of `db/` contents, so editing any `db/` file means a new template (built once, shared across agents and runs). Stale `codex_t_*` clones and old templates are cleaned up automatically.
- **Doubles go through `ConfigureTestServices`** (override it on the fixture); production code has no test switches. Time is never frozen: the database stamps comparison timestamps and the app uses `TimeProvider.System`; tests compute expected labels from the run's date.
- **Acceptance tests need the client built** (`pnpm run build` into `src/Codex.WebApi/wwwroot`); the fixture fails with that instruction if the bundle is missing. One Chromium per run, one browser context per class, one page and trace per test (trace kept only on failure).
- Selectors are `data-testid` only: shell ids live in `src/Codex.Client/src/testIds.ts` and `src/Codex.TestSupport/TestIds.cs`, lane ids in the lane's own files; reach them through page objects.
- Naming: `Method_WhenCondition_ShouldOutcome`. Never weaken or delete existing tests (see `.claude/skills/preserve-existing-tests/`).

## Modules and DI

- Features register through `IServiceModule` classes (public, parameterless constructor) in `Codex.WebApi` or `Codex.Application`; `Program.cs` finds them by assembly scan and is never edited per feature. **Feature endpoints are controllers** deriving from `ApiControllerBase` (#98; `Features/Ai/AiIntegrationsController.cs` is the pattern): one per resource in the feature's folder, primary-constructor injection, attribute routes with the full `api/...` template and the same parameter names and constraints as the access sweep rows, one-line actions with `[ProducesResponseType]`. `MvcServices` keeps them answering as minimal APIs did (no implicit `[Required]`, a null result is 200 with no body, ApiError bodies, JSON-only bodies, blank strings kept); form reading sits in a static helper next to the controller (Sonar S6932 bans `Request.Form` in controllers). `IEndpointModule` (minimal APIs) is only for non-MVC endpoints: the SignalR hub, `/mcp` and health.
- Own types register with Agoda.IoC attributes (`[RegisterSingleton]`/`[RegisterPerRequest]`/`[RegisterTransient]`) on the class, scanned in both assemblies.
- **Read configuration at resolve time** (`sp => sp.GetRequiredService<IConfiguration>()`), not in `AddServices`: test overrides are appended after registration code runs.
- Data access is Npgsql + Dapper with parameters over the registered `NpgsqlDataSource`. No EF Core, no string-built SQL for values. Dapper maps result columns onto record constructors by name and exact type: `timestamptz` → `DateTimeOffset` works (`DapperTypeHandlers`), but cast to the DTO's type in SQL otherwise (`count(*)::int`). Pass timestamps as UTC (Npgsql rejects other offsets).
- `ICurrentUser.Id` is the signed-in user (the cookie's claim; on `/mcp` the bearer token's user; the configured MCP user on stdio). **Access (#80):** every command or query that takes a book id, or the id of anything inside a book, calls `IBookAccess.RequireAsync(…, BookRole minimum)` first (before validating the body): reads `View`, content and settings changes `Write`, lifecycle and sharing `Owner`. No access is `not_found`; a role below the minimum is `forbidden`. Lists read the `book_access` view (owner, direct and series grants), not `owner_id`. A new id-bearing `/api` route needs a row, with its minimum role, in `AccessSweep` (`docs/auth.md`).

## Important notes

- **One top-level type per file**, named after the type. Only exception: an interface with exactly one implementing class may sit in that class's file, above it.
- **Controllers are one-liners** delegating to services; contract declared via attributes (`[ProducesResponseType]` etc.). Services throw `ApiException` (see Errors above), and `ApiErrorServices` maps it to `ApiError` and the status.
- **API view models and one request per screen**: see `.claude/skills/api-response-for-browser/`.
- **UTC everywhere.** Everything from the BFF back is UTC; time zones exist only where the BFF formats a label or converts an entered date. No `Date` objects in the SPA: see `.claude/skills/utc-everywhere/`.
- **The clock is `TimeProvider`.** `DateTime.Now`/`UtcNow` and friends are banned at build time.
- **Outbound HTTP goes through a named `HttpClient`**, so a test stubs that socket by name rather than the code growing a test branch.
- **Env vars are prefixed `CODEX_`** (`CODEX_DB_CONNECTION`, `CODEX_DB_MIGRATE`, `CODEX_BLOB_ROOT` (the blob store's folder: `artifacts/blobs` in dev, `/data/blobs` in compose, a per-host temp folder in tests via `CodexHost.BlobRoot`; a relative path resolves against the content root), `CODEX_SEQ_URL`, `CODEX_SEQ_API_KEY`, `CODEX_EVENTS_LISTEN` (default `true`: run the LISTEN half of the cross-process book-event bridge; the worker sets it `false`; see `docs/events.md`), `CODEX_ROLE` (`web`, `worker` or `all`), `CODEX_DATA_PROTECTION_DIR` (the key ring that encrypts users' AI keys; `docs/ai-integrations.md`), `CODEX_AI_ALLOW_LOCAL_ENDPOINTS` (`true` lets a user's AI base URL be a local address; `docs/ai-integrations.md`), `CODEX_ADMIN_EMAIL` / `CODEX_ADMIN_PASSWORD` (first admin at startup, `docs/auth.md`), `CODEX_MCP_USER_EMAIL` (the user stdio and tokenless local `/mcp` act as; default JD), `CODEX_MCP_TOKEN` (a personal access token stdio acts as instead, with its scopes; `docs/mcp.md`), the print toolchain settings (`CODEX_PANDOC`, `CODEX_TECTONIC`, `CODEX_SANDBOX`, `CODEX_TEMPLATES_ROOT`, …) and `CODEX_MCP_MAX_GENERATIONS` (`docs/mcp.md`)); the OpenTelemetry settings are the standard unprefixed ones (`OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_PROTOCOL`, `OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_HEADERS`; `docs/observability.md`); `CODEX_TEST_DB` points tests at a long-lived Postgres server. Logs go to the console, and to Seq too once `CODEX_SEQ_URL` is set.
- **`TODO:` comments mark temporary behaviour** (rule S1135 is off for that reason); each names what replaces it.
- **Playwright screenshot baselines are environment-pinned.** `toHaveScreenshot()` may fail locally even on unchanged code; regenerate baselines only inside the `mcr.microsoft.com/playwright:v1.62.0-resolute` image CI uses.
- DI by Agoda.IoC: [github.com/Agoda-com/Agoda.IoC](https://github.com/Agoda-com/Agoda.IoC).
